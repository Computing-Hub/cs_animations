Class

A blueprint or template. It defines the attributes (data) and methods (procedures and functions) that every object of that type will have. No data is stored until an object is made.

Object

An instance of a class, created by new (instantiation). Each object has its own copy of the attributes, so two accounts can hold different balances while sharing the same methods.

Encapsulation

Attributes are made private so they can only be read or changed through the class's public methods (getters and setters), which can validate the change.

Inheritance

A subclass inherits the attributes and methods of its parent (superclass) and adds or changes some. super.new() runs the parent's constructor.

Polymorphism

Objects of different classes respond to the same method call in their own way, because a subclass can override a method. Code can treat them all as the parent type.

What a constructor is for

        
    
          
  • It is a special method that runs automatically when new creates an object. In OCR pseudocode it is called new; in Python it is __init__.
    • 
          
  • Its job is to put the object into a valid starting state: every attribute gets a value, usually from the parameters.
    • 
          
  • A subclass constructor calls super.new(...) first so the parent's attributes are set up, then sets its own.
    • 
          
  • The variable on the left of = stores a reference to the new object. Two variables can refer to the same object; two new calls make two separate objects.

Encapsulation in the mark scheme

        
    
          
  • Attributes are declared private, so they cannot be read or changed directly from outside the class.
    • 
          
  • Access is only through public methods: a getter returns the value, a setter changes it.
    • 
          
  • The setter can validate, so the object can never be put into an invalid state (a negative score, an overdrawn account that should not be).
    • 
          
  • The class can change how it stores its data without breaking the code that uses it, because that code only ever used the methods. This reduces bugs and makes large programs easier to maintain.
    • 
          
  • Python note: two leading underscores (__score) mark an attribute as private. Python does not enforce it as strictly as other languages, but the exam treats it as private.

What inheritance gives you

        
    
          
  • The subclass gets every attribute and method of the parent without writing them again: SavingsAccount can deposit even though it never defines it.
    • 
          
  • It can add new attributes and methods (interestRate, addInterest).
    • 
          
  • It can override a method by defining one with the same name (describe, canWithdraw). The subclass version replaces the parent's for objects of the subclass.
    • 
          
  • super.new(...) and super.describe() call the parent's version from inside the subclass.
    • 
          
  • A subclass cannot touch its parent's private attributes directly. It uses the parent's public methods, such as getBalance(). That is encapsulation applying to subclasses too.
    • 
          
  • Benefits to state: code reuse, less duplication, easier maintenance (fix the parent once), and a clear "is a" relationship between types.

Polymorphism in the exam

        
    
          
  • Definition: the same method name can produce different behaviour depending on the class of the object it is called on.
    • 
          
  • In OCR's examples it comes from overriding: a subclass redefines a method inherited from its parent.
    • 
          
  • A variable or array of the parent type (Account) can hold objects of any subclass, so one loop handles them all.
    • 
          
  • Dynamic: which version runs is decided by the object at run time, not by the type written in the code.
    • 
          
  • Benefit: new subclasses can be added without changing the code that uses them.

    Exam tips and common mistakes
    
    
      
  • Class versus object. The class is the definition; an object is a real thing made from it with new. "Account is a class; acc1 is an object (an instance of Account)." Never say the class stores the balance.
    • 
      
  • Attribute versus method. Attributes are the data an object holds; methods are what it can do. In a class diagram attributes come first, methods second.
    • 
      
  • Write the constructor as new in OCR pseudocode: public procedure new(...). In Python it is def __init__(self, ...). Do not mix the two.
    • 
      
  • Instantiation syntax: acc1 = new Account("Ava", 100). The arguments must match the constructor's parameters in number and order.
    • 
      
  • Calling methods: acc1.deposit(50), with the object name, a dot, the method and brackets. A function call returns a value, so use it in an expression or print: print(acc1.getBalance()).
    • 
      
  • Private means private everywhere outside the class, including subclasses. Give the subclass what it needs through public getters and setters, or call the parent's public methods.
    • 
      
  • Inheritance syntax: class SavingsAccount inherits Account, and super.new(...) as the first line of the subclass constructor. Python: class SavingsAccount(Account): and super().__init__(...).
    • 
      
  • Overriding versus overloading. Overriding (same name, redefined in a subclass) is what OCR means by polymorphism. Overloading (same name, different parameters, in one class) is not needed in OCR pseudocode.
    • 
      
  • Explain, don't just name. "Encapsulation" on its own earns nothing. Say what is private, how it is accessed, and why that helps (validation, fewer bugs, easier changes).
    • 
      
  • Advantages of OOP that get marks: reuse through inheritance, easier maintenance and testing of self-contained classes, encapsulation protecting data, polymorphism letting code handle new types, and classes matching real-world things which helps teams split the work.
