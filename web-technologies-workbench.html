HTML: structure and content

Tags mark up what each part of the page is: a heading, a paragraph, an image, a form. Attributes such as id and class label elements so CSS and JavaScript can find them.

CSS: appearance

Rules made of a selector and properties say how elements look: colour, size, font, borders. Kept in a <style> block or an external file linked with <link>.

JavaScript: behaviour

Code that runs in the browser (client-side). It reads what the user typed, does a calculation and writes the result back into the page through the DOM: document.getElementById("id").

Rules of HTML worth marks

        
    
          
  • A page is <html> containing a <head> (information about the page: the <title>, links to CSS, scripts) and a <body> (everything that is displayed).
    • 
          
  • Most tags come in pairs: an opening tag and a closing tag with a slash, <p>…</p>. <img>, <input> and <link> have no closing tag.
    • 
          
  • Attributes go inside the opening tag as name="value": <img src="logo.png" alt="Club logo">.
    • 
          
  • id must be unique on the page and is how JavaScript finds an element. class can be shared by many elements and is mostly used by CSS.
    • 
          
  • Nest tags properly: close the inner tag before the outer one. <li> only lives inside <ul> or <ol>.
    • 
          
  • Give every <img> an alt: it describes the image for screen readers and shows if the file is missing.

How CSS is attached to a page

        
    
          
  • External: a separate file, linked in the head: <link rel="stylesheet" href="styles.css">. One file styles every page of the site, so a change is made once; the browser can cache it.
    • 
          
  • Internal: a <style> block in the head of one page. Good for a one-off page; the rules only apply there.
    • 
          
  • Inline: a style="…" attribute on a single tag. Quick, but mixes appearance into the HTML and cannot be reused.
    • 
          
  • Which rule wins? An id selector beats a class selector, which beats an element selector. If two rules have the same type of selector, the one written later wins.

The JavaScript you need

        
    
          
  • var total = 0; declares a variable. (let is also accepted.)
    • 
          
  • function calc() { … } defines a function. It runs only when something calls it.
    • 
          
  • onclick="calc()" on a button calls the function when the button is clicked.
    • 
          
  • document.getElementById("num").value reads what the user typed into an input (always a string).
    • 
          
  • parseInt(text) or parseFloat(text) turns that string into a number. Without it, "12" + "3" is "123".
    • 
          
  • document.getElementById("result").innerHTML = "…" writes into the page.
    • 
          
  • alert("message") pops up a message box.
    • 
          
  • if (x == "") { … } else { … } for a decision; == compares, = assigns.

Client-side processing (JavaScript in the browser)

        
    
          
  • Runs on the user's computer, so it responds instantly and works without a round trip to the server.
    • 
          
  • Reduces the load on the server and the amount of data sent across the network.
    • 
          
  • Can check a form before it is sent (validation), change the page, respond to clicks.
    • 
          
  • But: the user can read, change or switch off the script, so it cannot be trusted for security, and it cannot reach the server's database directly.
    • 
          
  • Different browsers may behave differently.
    • 
        

      

      

        
Server-side processing (code on the web server, e.g. Python, PHP)

        
    
          
  • Runs on the server, so the user never sees the code and cannot change it: suitable for passwords, payments, anything that must be trusted.
    • 
          
  • Can access databases and files on the server and keep data consistent for every user.
    • 
          
  • Does not depend on the user's browser or device.
    • 
          
  • But: every request travels across the network, so it is slower, and a busy site puts heavy load on the server.
    • 
        

      

      

        
The point examiners want

        
    
          
  • Validate on the client for speed and a better user experience, and again on the server because client-side checks can be bypassed.
    • 
          
  • Searching a database, logging in and storing an order must be server-side. Checking an email address has an @ or a field is not empty can be client-side.

    Exam tips and common mistakes
    
    
      
  • Match the ids. The id in getElementById("result") must be exactly the id in the HTML, including case. A mismatch returns null and the script stops with an error.
    • 
      
  • Inputs give strings. .value is text. Convert with parseInt() or parseFloat() before doing arithmetic, or "12" + "3" becomes "123".
    • 
      
  • Put the function somewhere it can be called. Define it in the <script> and call it from onclick="name()" with the brackets.
    • 
      
  • Brackets and braces. Every ( needs a ), every { a }. Statements end with a semicolon. Markers forgive small slips but not a missing block.
    • 
      
  • Closing tags. <p>, <h1>, <a>, <div>, <li>, <ul>, <form> all need closing. <img> and <input> do not.
    • 
      
  • Selectors. A full stop for a class (.note), a hash for an id (#box), nothing for an element (p). Property and value are separated by a colon and end with a semicolon.
    • 
      
  • Say where the CSS lives. "External stylesheet linked with <link> in the head" is the phrase.
    • 
      
  • Client versus server. Give a reason, not just a name: "server-side, because the password must be checked where the user cannot see or change the code".
    • 
      
  • Not examined here: frameworks, CSS layout, JavaScript arrays and loops in detail, server languages themselves. The HTML and CSS lists above are the whole specification list.
